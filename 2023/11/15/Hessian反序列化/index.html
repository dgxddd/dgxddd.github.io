Hessian反序列化

2023-11-15
JAVA安全
Hessian

Hessian反序列化

环境

序列化

HessianOutput

在com.caucho.hessian.io.HessianOutput#writeObject中查看，判断序列化对象是否为null，不是的话，根据对象所属类，调用_serializerFactory.getSerializer，去获取序列化器。

在com.caucho.hessian.io.SerializerFactory#getSerializer，优先从缓存Map中搜索是否有当前Class对应的序列化器，有的话直接返回。没有的话，调用loadSerializer，根据类型获取对应的序列化器，然后put进缓存Map中，方便下次直接取。

com.caucho.hessian.io.SerializerFactory#loadSerializer。根据类名称直接获取序列化器

并在能够直接获取的是39个基本类型

com.caucho.hessian.io.ContextSerializerFactory#getCustomSerializer获取自定义反序列化器

很多if，判断是否为指定类型，以此判断是否调用其他内置序列化器。自定义类会走到最后getDefaultSerializer。

首先判断是否已配置全局默认序列化器，有则直接返回；接着校验类合法性，若目标类未实现Serializable且未开启_isAllowNonSerializable，就抛出异常，开启该配置即可绕过接口限制、扩大可序列化类范围，最后结合_isEnableUnsafeSerializer开关与类是否存在writeReplace方法，优先选用高性能的UnsafeSerializer，不满足条件则使用标准的JavaSerializer。

后面我们跟进UnsafeSerializer，从_serializerMap软引用缓存中获取指定类的UnsafeSerializer实例；若缓存不存在，则根据类是否标注@HessianUnshared注解，创建对应的UnsafeSerializer或UnsafeUnsharedSerializer

我们查看一下UnsafeSerializer方法，调用introspect，这个方法名比较特殊，有一个类叫java.beans.Introspector，专门用于“内省”，即获取JavaBean的公开属性和方法。跟进introspect：

该方法通过内省机制遍历指定类及其所有父类的字段，过滤掉static和transient字段，并将剩余字段按类型分为两组：基本类型及 java.lang 开头的基础包装类字段存入 primitiveFields，其他复杂对象类型字段存入 compoundFields，为后续高性能序列化做字段分类准备。

序列化器获取完毕，现在开始序列化,com.caucho.hessian.io.UnsafeSerializer#writeObject,先获取对象的实际类，然后写入类名（告诉反序列化端这是什么类）。writeObjectBegin 返回一个 ref 值，用来判断 Hessian 协议版本和是否需要写入类定义。

跟进一下writeObjectBegin，该方法是 Hessian 1.0 协议下的对象序列化开头，通过写入Map 开始标记并带上类名，直接返回 -2 标识使用旧版协议，让上层走兼容的 writeObject10 完成序列化。

因为ref返回的是-2，所以进入writeObject10：

跟进writeObject10，该方法按照 Hessian 1.0 协议 序列化对象，循环遍历所有预解析的字段，依次写入字段名和对应字段值，最后写入 Map 结束标记完成整个对象的序列化。其中 transient 和 static 修饰符的字段并没有添加到 _fields[] 数组中，所以不会进行序列化

到这个序列化就结束了。

Hessian2Output

com.caucho.hessian.io.Hessian2Output#writeObject先判断对象是否为 null 并写入空值，不为 null 则通过序列化器工厂找到对应类型的序列化器

跟进getObjectSerializer方法看看这个在这里调用了getSerializer方法我们继续跟进发现这个就和前面HessianOutput一样流程。

直到com.caucho.hessian.io.Hessian2Output#writeObjectBegin才是不一样的，通过类名缓存实现：首次写入类定义标记C和完整类名并返回 - 1，后续仅用数字引用 ID 传输，大幅减少数据量。

最后ref返回-1，先写入类的字段定义（只发一次），再写入对象开始标记，最后按顺序只写字段值，实现高效序列化。

跟进writeDefinition20和writeObject10的区别是writeObject10 按 Hessian1.0 协议循环写字段名 + 字段值并以 Map 结束，writeDefinition20 按 Hessian2.0 协议只写一次字段名作为类定义，后续序列化仅传值。

最后在com.caucho.hessian.io.UnsafeSerializer#writeInstance直接按预定义顺序调用字段序列化器写入字段值，不传输任何字段名，实现高效紧凑的序列化

反序列化

HessianInput

首先我们跟进com.caucho.hessian.io.HessianInput#readObject()，因为我们在HessianOutput会设置首字母是M

我们继续跟进com.caucho.hessian.io.SerializerFactory#readMap，会获取反序列化器，然后根据获取情况进行反序列化

继续跟进com.caucho.hessian.io.SerializerFactory#getDeserializer(java.lang.String)。先判断 type 是否为 null，为空直接返回，从 _cachedTypeDeserializerMap 缓存取→ 取到直接返回（最快），从 _staticTypeMap 取→ 这里是 String/Integer 等基础类型的反序列化器，判断是否是数组 → 是数组就创建数组反序列化器，最后走默认流程：加载类 loadSerializedClass(type)调用 getDeserializer(cl)

跟进com.caucho.hessian.io.SerializerFactory#getDeserializer(java.lang.Class)根据 Class 对象获取反序列化器：先查类级别缓存，缓存未命中则通过 loadDeserializer(cl) 加载对应反序列化器，存入并发缓存后返回，保证每个类只创建一次反序列化器。

跟进com.caucho.hessian.io.SerializerFactory#loadDeserializer，loadDeserializer 按优先级匹配反序列化器，普通 Java 对象最终会走到默认逻辑，拿到 UnsafeDeserializer，

跟进com.caucho.hessian.io.SerializerFactory#getDefaultDeserializer，首先判断类是否为 InputStream 并返回专用反序列化器，随后根据 _isEnableUnsafeSerializer 开关决定使用高性能的 UnsafeDeserializer

跟进com.caucho.hessian.io.UnsafeDeserializer#UnsafeDeserializer，首先将传入的目标类赋值给类型变量_type，接着通过getFieldMap方法解析目标类的所有字段，并生成对应的字段反序列化器存入_fieldMap，完成字段解析与映射的预加载，然后查找类中是否存在readResolve方法（用于反序列化后返回自定义对象），若存在则将其设为可访问，

跟进com.caucho.hessian.io.UnsafeDeserializer#getFieldMap看是如何获取字段的，通过反射获取类的属性，把属性名和对应的反序列化器放到fieldMap里备用

拿到反序列化器，就要执行 反序列化器的 readMap() 方法，this.instantiate() ，这个就是通过 unsafe 实例化类，我们都知道 unsafe 是不会执行类构造器和 getter、setter 等方法的，所以 反序列化链的条件 所有的调用不依赖类中 readObject 的逻辑，也不依赖 getter/setter 的逻辑 也就理解了

在com.caucho.hessian.io.UnsafeDeserializer#readMap(com.caucho.hessian.io.AbstractHessianInput, java.lang.Object)这里也能看出是把自定义对象当作Map来还原的。先取出属性名，然后从filedMap取出对应反序列化器，然后deser.deserialize反序列化值，也是通过Unsafe方法根据偏移量直接还原。同时，这里也是可以重新resolve方法，来执行一些自定义操作。

如果反序列化的是HashMap，执行 MapDeserializer#readMap 方法

跟进com.caucho.hessian.io.MapDeserializer#readMap，会执行 map.put()，map.put 是会执行 putVal ==> equals、hash == > hashcode 。HashMap可以触发key.hashCode，key.equals；如果是TreeMap，可以触发compareTo

HessianInput2

使用hashmap会进入到H

最后也是到后进行map.put
